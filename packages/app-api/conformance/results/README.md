# Conformance results (run 12, conformance phase I6: the 364-vector suite with the receipt group, receipt verification measured, Tiers 1 and 2 for every configuration)

`conformance-matrix.md` / `.json` and `results.json` come from one invocation of the suite's own
command line against the JSON-RPC adapter in `../`; the files are regenerated by re-running it, never edited by hand.
Suite state run against (branch `conformance/i5-rerun-results`): 364 vectors (Tier 1 302: 243 gating and 59 CLARIFY; Tier 2 62 in five named sub-groups: attested, profile-window, profile-ceremony, profile-witness-share, profile-p384); SHOULD mismatches are reported as advisories (none observed) and the CLI runs Tiers 1 and 2 for every adapter; the suite increment I1 contract: the clock capability, a declared window, the run salt and the vacuous-pass rule.
The adapter declares `clock` (it has an injectable clock; never `clockFree`) and its window, `capabilities.window` = 300 s maximum age, 60 s skew, 30 days expiry horizon,
read from the pipeline's own pinned constants, so it equals the profile pins: the matrix rows carry `window` (in `conformance-matrix.json`) with no window difference, and no fixture row is SKIP for a window difference.
Every run used the default random salt (each run's salt is stored in `results.json` as `salt`); an earlier rerun of every configuration with a fixed `--salt` gave per-vector results identical to the random-salt runs (not repeated for this run).
Every matrix cell is green (no FAIL, no KNOWN-FAIL); there is no `*` vacuous-pass annotation.
The adapter declares `capabilities.ceremony.proposerApproves: false` (the stack's native model: a begin records no approval, every named
administrator co-signs) and the status task (`statusType`, `statusPayload`), so CER-014 pins the declaration, CER-015 and CER-016 run and CER-002 is SKIP.

## Rows

Two rows, `truststackers-agent-didkey` and `truststackers-agent-scidvh` (a `did:key` or the real `did:scid:vh`
connection identifier). Each merges two runs by the suite's rule (runs sharing `capabilities.implementation`): the attested
