# Conformance results (run 2, conformance phase P8b: 203-vector suite)

`conformance-matrix.md` / `.json` and `results.json` come from one invocation of the suite's own
command line against the JSON-RPC adapter in `../` (`../server.ts` has the options). Suite folder state:
203 vectors; the files here are regenerated by re-running the command, never edited by hand.

    S="stdio:NODE_NO_WARNINGS=1 node --conditions=development --experimental-strip-types --loader ./test-loader.mjs conformance/server.ts"
    node <suite>/src/runner/cli.ts --timeout 60000 --out conformance/results \
      --adapter "$S --attested --identity key --name truststackers-agent-didkey-attested" \
      --adapter "$S --attested --name truststackers-agent-scidvh-attested" \
      --adapter "$S --identity key --name truststackers-agent-didkey-tier1" \
      --adapter "$S --name truststackers-agent-scidvh-tier1"

Cell format: roll-up (FAIL > KNOWN-FAIL > PASS > CLARIFY > SKIP) then pass/fail/skip/known-fail/clarify.

## Rows

- `didkey-attested`, `scidvh-attested`: the agent boundary claiming Tier 2, with a `did:key` or the
  real `did:scid:vh` connection identifier. Both run Tier 1 and Tier 2. The scid:vh rows pass Tier 2 now
  that the suite verifies replies from the DID document `provision` returns (the earlier 96 failures
  were that suite limitation).
- `didkey-tier1`, `scidvh-tier1`: a server that does not claim `attested`. Only these rows run the 15
  vectors that assert Tier 1 behaviour an attested server does not show (PRF-108, DUP-101..113,
  VRC-PRO-011); the attested rows SKIP them and the matrix says so. Full Tier 1 coverage is the union.

## What each column was measured by

| Column | Carrier and code under test | Binding |
|---|---|---|
| framework (ENV, RSP, ERR, ID, LIF, CTRL, TIME, DUP, PRF) | **Fixture carrier.** The suite's conformance widget task is served by a fixture handler placed behind the real pipeline, proof verifier, accepted-id store, signer and recorder. The envelope, freshness, duplicate, error and proof code is real; the task behind it is not a task the agent offers in production. DUP-007/008 use the `fault.claimStore` hook, which makes the real accepted-id store's database calls fail. | in-process |
| vrc-propose (VRC-PRO, NS, AUTHZ) | **Real task.** `vrc/relationships/propose` through `VrcProposeService` on the app database, with the transaction log in a second temp database, per-exchange did:peer:4 DIDs, consent via the `policy` and `consent` triggers. | in-process |
| vrc-issue (VRC-ISS) | **Real task.** The VRC issue handler and `VrcReceiveParticipant` on `TransactionManager` / `TransactionCoordinator`. | in-process |
| vrc-witness-share (WSH, TD) | **Real task.** The witness-share handler and `WitnessShareParticipant`. TD vectors are driven through witness-share as carrier. | in-process |

No cell was measured over HTTPS: the adapter calls the pipeline directly, and `bindings` is declared
`in-process` (no BND vectors exist yet). Nothing is mocked below the boundary; databases are temp SQLite
files, the clock is injected, and `restart` closes and reopens both database files.

  Not an implementation gap; no exception entry. See the P8b report for the decision.
- CLARIFY (14, non-gating, all observed matching): AUTHZ-002, WSH-019, ERR-005, ERR-008, DUP-007,
  DUP-008, VRC-PRO-016, 017, 018, VRC-ISS-003, 020, 021, 022, 023.
- SKIP: PRF-002..005 (ES256 not claimed); tier-gated vectors at the other tier; the 15 non-attested
